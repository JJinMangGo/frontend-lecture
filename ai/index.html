채팅으로만 AI를 써 본 사람도 이해할 수 있도록, 쉬운 비유와 정확한 정의를 연결했어. 읽고 나면 문제로 확인해 보자.

전체 강의 홈5문제 풀기
01 · 기본 구조

AI, 생성형 AI, LLM은 어떻게 다를까?

AI는 사람의 지능이 필요한 일을 컴퓨터로 수행하도록 만드는 넓은 분야야. 생성형 AI는 글, 이미지, 코드 같은 결과물을 만들지. LLM은 대규모 언어 데이터를 학습한 언어 모델이야.

비유: AI가 학교 전체라면, 생성형 AI는 창작 수업이고 LLM은 언어를 다루는 데 특화된 학생이라고 생각해 봐. 정확히는 LLM은 언어 모델이라는 기술 분류야.

모델과 서비스도 달라

모델은 학습을 통해 만들어진 핵심 계산 시스템이고, ChatGPT 같은 서비스는 그 모델을 사람들이 쓰기 쉽게 만든 제품이야.

02 · 사용하기

프롬프트, 토큰, 컨텍스트

프롬프트

AI에게 건네는 요청과 지시. 과제 지시서처럼 생각해.

토큰

AI가 텍스트를 처리하는 기본 단위. 돈 자체가 아니지만 사용 요금 계산에 쓰이기도 해.

컨텍스트 윈도우

모델이 한 번에 처리하는 정보량의 한도. 크기가 정해진 작업 책상과 비슷해.

꼭 기억: Training은 모델 학습, Inference는 학습된 모델의 실행이야. Reasoning은 문제를 분석해 해결하는 과정으로, Inference와 같은 뜻은 아니야.
03 · 연결하고 일시키기

API, MCP, RAG, 에이전트

API

프로그램끼리 기능이나 데이터를 주고받는 연결 규칙. 주문 창구를 떠올려 봐.

MCP

AI 애플리케이션이 외부 도구와 데이터를 공통 규격으로 사용하는 표준. 공통 연결잭과 비슷해.

RAG

외부 자료를 찾아 그 정보를 참고해 답변을 생성하는 방식. 도서관에서 책을 찾아 답하는 모습이야.

AI 에이전트는 목표를 수행하기 위해 판단하고 도구를 사용할 수 있는 시스템이야. 스킬은 작업 매뉴얼, 하네스는 실행을 지원하는 도구·규칙·검증 환경, HITL은 사람이 중요한 판단에 개입하는 방식이야.

실제 사례: AI에게 '우리 회사 최신 규정을 알려줘'라고 하면, 문서를 검색해 참고하는 방식은 RAG야. 회사 문서 시스템의 도구에 AI가 연결되는 방법으로 MCP를 사용할 수도 있지만, RAG에 MCP가 필수는 아니야.
