Claude Code나 피클은 사용자가 이용하는 AI 에이전트 제품의 사례예요. 반면 LangGraph, CrewAI, OpenAI Agents SDK, eve는 개발자가 그런 종류의 에이전트를 만들 때 활용할 수 있는 도구예요. 특정 제품이 이 프레임워크를 사용했다는 뜻은 아니에요.

AI 모델+개발 프레임워크+개발자의 기능·권한 설계→AI 에이전트 서비스
PART 01

에이전트 개발 프레임워크는 뭘까?

우리는 Next.js 같은 프레임워크를 활용해 웹사이트를 만들어요. AI 에이전트도 비슷해요. 사용자 요청을 이해하는 모델에 파일 읽기, 코드 수정, 외부 서비스 조회, 실행 상태 기록, 승인 요청 등의 기능을 붙여야 실제 작업을 수행할 수 있어요. 이때 공통 실행 구조를 제공하는 도구가 AI 에이전트 개발 프레임워크예요.

쉽게 이해하기

Next.js가 웹사이트 그 자체는 아닌 것처럼, eve도 완성된 Claude Code가 아니에요. 프레임워크는 개발 재료와 공통 구조를 제공하고, 실제 에이전트의 기능과 화면은 개발자가 만들어요.

핵심 기억하기

LLM = 언어를 처리하는 모델 / 에이전트 = 목표에 따라 도구를 사용하며 일을 수행하는 프로그램 / 프레임워크 = 그런 프로그램을 개발하는 공통 기반 / 하네스 = 실행·도구·상태·검사·승인 등을 관리하는 구조.

PART 02

대표적인 개발 프레임워크는 어떤 차이가 있을까?

모두 에이전트를 만드는 데 활용할 수 있지만 설계의 중심이 달라요. 아래는 특징을 이해하기 위한 비교이며, 표에 적힌 기능만 제공한다는 뜻은 아니에요.

도구설계에서 강조하는 부분학생용 예시
LangGraph작업 흐름, 상태 저장, 중단·재개, 사람 승인주문 조회 → 환불 조건 검사 → 사람 승인 → 처리
CrewAI역할을 나눠 협업하는 에이전트와 작업 흐름자료 조사 담당 · 기획 담당 · 검토 담당
OpenAI Agents SDK도구 호출, 에이전트 간 작업 전달, 검증과 실행 추적문의 분류 에이전트가 담당 에이전트에 전달
Vercel eve하네스와 실행 지속성, 서비스 통합·배포·관찰웹사이트에 에이전트를 넣고 사용·비용·승인 현황 확인
오해하지 않기

LangGraph도 실행 복구와 HITL을 지원해요. eve가 이 기능들을 처음 발명한 것은 아니에요. 선택할 때는 개발 언어, 필요한 기능, 배포 환경, 운영 비용, 팀의 경험을 함께 봐야 해요.

PART 03

Vercel eve 1.0은 뭐가 다를까?

Vercel은 2026년 11월 eve 1.0을 정식 공개했어요. 기존 프레임워크와 달리 모든 기능을 처음 만들었다는 뜻이 아니라, 에이전트의 하네스와 운영 환경을 Vercel 서비스에 연결해 개발·배포하기 쉽게 구성했다는 것이 발표의 핵심이에요.

① 협업하고 승인받기

Slack·Teams 같은 메시지 채널에서 요청을 받고, 중요한 행동에는 담당자의 승인을 요청할 수 있어요.

② 웹서비스에 통합하기

Next.js 같은 웹 프레임워크를 사용하는 서비스 안에 에이전트를 넣을 수 있어요. 기존 웹사이트가 자동으로 AI 서비스로 바뀌는 건 아니에요.

③ 실행 기록을 관찰하기

모델 사용량과 비용, 도구 실행, 승인 대기 등을 확인할 수 있어요. 중간에 작업이 끊겼을 때 이어가도록 상태를 저장하는 기능도 제공해요.

하네스와 연결하기

에이전트가 어떤 도구를 쓰는지, 어느 단계에서 멈추거나 다시 시작하는지, 어떤 행동에 사람의 승인을 받는지를 설계하고 실행하는 구조가 하네스예요. eve는 이런 구조를 구현한 프레임워크 중 하나예요.

핵심 기억하기

eve는 새로운 AI 모델도, 완성된 코딩 에이전트도 아니에요. 에이전트를 개발하고 운영할 때 사용할 수 있는 오픈소스 프레임워크예요.

PART 04

내 리뉴얼 사이트에 적용한다면?

학생이 리뉴얼 중인 쇼핑몰에 환불 에이전트를 추가한다고 가정해 봐요. 고객이 “환불하고 싶어요”라고 입력하면 단순히 환불 방법을 설명하는 대신, 연결된 시스템과 허용된 권한 범위에서 아래 작업을 진행할 수 있어요.

주문 조회→환불 조건 확인→담당자 승인→처리·안내
기획 실습 · 3가지 질문

① 내가 리뉴얼하는 사이트에서 AI가 직접 수행하면 유용한 작업 하나는?
② 이 작업에 어떤 데이터·도구 접근이 필요한가?
③ 사람의 승인이나 최종 확인이 필요한 단계는 어디인가?

디자인·UX와 연결하기

에이전트가 작동한다고 좋은 서비스가 완성되는 건 아니에요. 사용자에게 실행 중인 작업, 사용된 정보, 승인 요청, 실패 및 취소 상태를 이해하기 쉽게 보여주는 화면도 설계해야 해요.
