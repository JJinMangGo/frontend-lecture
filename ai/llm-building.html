이 과정에서 배울 내용

기존 AI 1~6단계에서는 LLM, 토큰, RAG, MCP, 에이전트와 도구 활용을 배웠어요. 이번 과정은 모델을 실제로 어떻게 학습시키고 평가하는지에 집중합니다. 스탠퍼드 강의의 개념을 초급 학습자 눈높이로 재구성한 한국어 해설이며, 강의 전체의 문장별 번역은 아닙니다.

데이터→사전학습→추가학습→평가→서비스
UNIT 01 · LANGUAGE MODELING

AI는 어떻게 다음 문장을 만들까?

언어 모델은 앞서 나온 토큰들을 바탕으로 다음 토큰이 등장할 확률을 계산하고, 선택된 토큰을 이어 붙이며 텍스트를 생성해요.

토큰(Token)

문장을 모델이 처리할 수 있도록 나눈 단위. 단어 전체일 수도, 단어의 일부일 수도 있어요.

자기회귀(Autoregressive)

이미 생성한 내용까지 문맥으로 사용하며 다음 토큰을 순서대로 예측해요.

손실(Loss)

모델의 예측과 실제 학습 데이터의 다음 토큰이 얼마나 다른지 나타내요.

토큰화는 왜 필요할까?

모든 단어에 고유 번호를 주면 오타나 낯선 단어 처리에 문제가 생길 수 있고, 글자 하나씩 나누면 시퀀스가 길어져요. 강의에서는 자주 함께 등장하는 토큰 쌍을 합치는 BPE(Byte Pair Encoding)를 소개해요.

아래는 단어를 공백과 구두점으로 나누는 교육용 예시입니다. 실제 LLM의 BPE 토크나이저와 결과가 다릅니다.

UNIT 02 · DATA PIPELINE

AI는 무엇을 배우고, 어떤 데이터를 버릴까?

‘인터넷 전체로 학습한다’는 말은 간단하지만, 실제 웹에는 중복 문서, 메뉴·푸터, 깨진 텍스트, 개인정보, 품질이 낮은 자료가 많아요.

웹 수집→본문 추출→유해·민감정보 필터링→중복 제거→품질·분야별 선별

강의는 데이터 선별과 배합이 모델 품질에 큰 영향을 준다고 설명해요. 수집량만 늘리는 것이 아니라 어떤 문서를 남길지 결정해야 하죠.

웹 제작 실습으로 연결

한 페이지를 수집했다고 상상해 보세요. 반복되는 메뉴, 광고 배너, 푸터는 제외하고 본문 설명과 예제를 남기는 작업을 해 봐요. 검색·수집과 학습 데이터 정제는 같은 일이 아니에요.

생각해 보기

한 사이트에 동일한 홍보 문구가 1만 번 등장하면, 그대로 학습시키는 게 좋을까요? 왜 중복 제거가 필요한지 이야기해 보세요.

UNIT 03 · PRE-TRAINING

AI는 어떻게 학습하고 커질까?

사전학습(Pre-training)은 대량의 텍스트에서 다음 토큰을 예측하면서 모델의 가중치를 조정하는 과정이에요. 아직 ‘친절한 채팅 도우미’가 되도록 조정하는 단계는 아니에요.

파라미터

학습하면서 바뀌는 모델 내부의 수치예요.

학습 데이터량

얼마나 많은 토큰을 학습하는지 나타내요.

계산 자원

훈련에 필요한 GPU 연산, 메모리, 시간을 뜻해요.

스케일링 법칙(Scaling Laws)

강의에서 소개하는 경험적 법칙은 모델 크기·데이터·계산량이 커질 때 학습 손실이 어떻게 변하는지 예측하는 데 활용돼요. 무조건 모델만 크게 만드는 것이 아니라, 제한된 계산 예산에서 자원을 어떻게 배분할지도 중요한 질문이에요.

비유

시험을 준비할 때 교재 분량, 공부 시간, 문제 풀이량을 함께 고려하듯 모델 학습에서도 크기와 데이터, 계산량의 균형을 고려해요. 다만 사람의 학습과 AI 학습은 같은 원리는 아니에요.

UNIT 04 · POST-TRAINING

AI는 어떻게 ‘도우미’가 될까?

사전학습한 모델을 사용자의 지시를 따르고 유용한 답을 하도록 조정하는 작업을 추가학습(Post-training)이라고 해요.

SFT · 지도 미세조정

질문과 모범 답변처럼 원하는 응답의 예시로 학습해요.

RLHF · 인간 피드백 강화학습

사람의 선호를 반영한 보상 신호를 이용해 응답 행동을 조정해요.

DPO · 직접 선호 최적화

선호되는 답과 그렇지 않은 답을 비교해 모델을 직접 최적화해요.

디자인 수업에 적용

AI에게 같은 웹사이트 시안에 관한 두 가지 피드백을 생성하게 해 보세요. 단순히 ‘예쁘게 바꾸세요’보다 정렬·타이포·접근성을 근거로 설명한 피드백을 사람이 선호하는지 판단해 보는 활동이에요. 이는 RLHF 자체를 구현하는 실습은 아니고, ‘선호 비교’ 개념을 이해하기 위한 예시예요.

UNIT 05 · EVALUATION & SYSTEMS

AI가 잘하는지는 어떻게 확인할까?

학습 손실이 낮아지는 것만으로 모든 실제 작업에서 좋은 답을 한다고 결론 내릴 수는 없어요. 평가하려는 능력에 맞는 테스트가 필요해요.

Perplexity · 퍼플렉서티

언어 모델의 예측 불확실성을 나타내는 지표예요. 낮을수록 해당 평가 데이터의 다음 토큰을 더 잘 예측해요.

벤치마크

MMLU처럼 정답이 있는 다양한 문제로 모델의 수행을 비교해요.

데이터 오염

시험 문제가 학습 데이터에 포함되면 성능이 실제보다 높아 보일 수 있어요.

시스템 최적화

큰 모델을 GPU에서 효율적으로 훈련하고 빠르게 응답하게 하는 기술이에요.

디자인 결과물을 평가한다면?

같은 결과물도 평가 기준이 달라지면 점수가 바뀔 수 있어요. AI가 만든 웹페이지를 검토할 때는 정렬, 대비, 접근성, 사용 흐름, 요구사항 충족처럼 기준을 먼저 명시해 보세요. 자동 점수와 사람의 검수를 함께 활용할 수 있어요.

강의에서 기억할 결론

LLM 개발에서 모델 구조만 중요한 것은 아니에요. 실제 데이터 품질, 평가 설계, 계산 시스템까지 함께 다뤄야 좋은 서비스를 만들 수 있어요.
