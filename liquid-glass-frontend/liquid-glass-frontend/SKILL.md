# Liquid Glass Frontend

유리 표면은 배경을 **굴절**시키고, 가장자리에 **캐스틱 림**이 있고, 광원이 **움직인다**. 이 셋 중 하나라도 빠지면 그냥 반투명 회색 박스다. 아래 순서대로 만든다.

## 0. 웹 구현 기반

웹사이트/웹앱을 새로 만드는 요청이면 `website-building` 을 먼저 로드해 프로젝트 구조·타이포·배포를 그쪽 규칙에 따르고, 이 스킬은 표면·굴절·인터랙션 레이어로 얹는다. 기존 코드베이스 수정이면 기존 디자인 시스템과 컴포넌트 구조를 보존한다.

## 1. 아트 디렉션 먼저 (유리는 스타일이 아니라 재질)

유리를 쓰기 전에 정한다: 배경(유리가 굴절할 대상), 서페이스 위계(무엇이 떠 있고 무엇이 바닥인가), 액센트 1개.

- **유리는 떠 있는 것에만.** 내비/시트/오버레이/히어로 카드. 본문, 표, 폼 필드는 불투명하게 둔다.
- **배경이 없으면 유리도 없다.** 평면 단색 위 blur 는 아무것도 굴절하지 않는다. 사진, 다층 그라디언트, 절차적 메시 중 하나를 먼저 만든다.
- **타이포는 유리와 반대로 간다.** 표면이 유동적이니 활자는 단단하게: 기하학적 산세리프 1종, 웨이트 대비, 크기 3~4단, `letter-spacing: -0.02em` 수준의 타이트한 헤드라인.
- **색은 무채색 + 액센트 1.** 유리 자체가 이미 배경색을 끌어온다. 여기에 색을 더 얹으면 탁해진다.

## 2. 표면 만들기

`assets/liquid-glass.css` 를 프로젝트에 복사하고 `--lg-*` 토큰만 팔레트에 맞춰 바꾼다. 구조는 `assets/glass-component.html` 의 3레이어(`.lg__backdrop` / `.lg__sheen` / `.lg__content`)를 그대로 따른다. `filter` 와 `backdrop-filter` 를 같은 요소에 걸면 Safari 에서 깨진다.

표면 모드는 둘 중 하나다:

- `.lg--frost` — `backdrop-filter` 블러 유리. 배경을 미리 알 수 없는 곳(스크롤 콘텐츠 위 내비·시트·드롭다운)은 무조건 이것.
- `.lg--lens` — 배경을 클론해 SVG 변위 필터로 진짜 굴절. 히어로·고정 패널·모달처럼 배경이 고정된 곳에 사용. `--lg-x/--lg-y` 정합 스크립트가 필수다.

굴절을 구현할 때(= 요청에 왜곡/렌즈/liquid glass 가 포함될 때) `references/glass-recipes.md` 를 읽는다. 필터 체인, 모드별 폴백, 배경 정합, 성능 한계가 거기 있다. 특히 `backdrop-filter: url(#…)` 은 `CSS.supports` 가 true 를 주지만 Chromium 에서 실제 굴절이 일어나지 않으므로(실측) 그 경로에 의존하지 않는다.

렌즈 변위맵은 노이즈로 만들지 않고 스크립트로 생성한다. 표면 픽셀 크기당 한 번 실행:

```bash
python scripts/gen_glass_maps.py --width 420 --height 220 --radius 28 --bezel 26 --out-dir <project>/assets/glass
```

변위맵 PNG, 스펙큘러 림 PNG, 그리고 붙여넣을 `feImage`/`feDisplacementMap` 스니펫을 함께 출력한다.

## 3. 인터랙션

`references/interaction-motion.md` 를 읽고 상태 테이블(hover/press/focus/drag/exit)과 포인터 추적 스펙큘러를 구현한다. 인터랙션이 요청에 명시됐거나 UI 에 조작 요소가 하나라도 있으면 항상 읽는다.

## 4. 검증 게이트 (공유 전 전부 통과)

로컬 확인은 `file://` 이 아니라 HTTP 로 한다. `feImage` 가 `file://` 에서 맵을 못 읽어 굴절이 통째로 사라진다. Playwright 로 데스크톱 1280px·모바일 375px 스크린샷을 찍고 확인한다:

1. 유리판 뒤 배경이 실제로 **휘어** 보이는가(가장자리에서 최대, 중앙 0). 안 휘면 `scale` 이 낮거나, 맵 크기가 표면과 다르거나, 맵을 못 읽은 것이다.
2. 렌즈 모드에서 판 안쪽이 밖보다 밝거나 진해 "다른 이미지를 붙인 네모"로 보이지 않는가. 배경의 직선이 판 경계에서 이어지면 정합이 맞은 것(보정은 `saturate 130% / brightness 1.01` 근처가 안전).
3. 유리 위 텍스트가 최악의 배경 구간에서도 읽히는가(대비 4.5:1↑).
4. 필터 영역이 좁아 가장자리에 투명한 틈이 생기지 않았는가.
5. 굴절이 꺼진 환경(= `@supports` 폴백)에서도 표면이 완성돼 보이는가.
6. hover/press/focus 링이 전부 살아 있고 `prefers-reduced-motion` 에서 얌전한가.
7. 스크롤·리사이즈 후에도 렌즈 배경이 어긋나지 않는가.
8. 모바일에서 판이 화면을 잡아먹지 않고 blur 가 과하지 않은가.

## AI 티 제거 체크

이 목록에 걸리는 게 있으면 만들기 전에 지운다: 보라-핑크 그라디언트 배경, 애니메이션 그라디언트 보더, 무지개/네온 글로우, 이모지 아이콘, 떠다니는 파티클, 3개 균등 피처 카드 그리드, 모든 요소에 걸린 유리, 표면 하나에 blur+글로우+sheen+보더 전부 쌓기, 의미 없는 "Powered by AI" 카피.
